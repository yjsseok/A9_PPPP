# SJCAM M20 V1.3.1 개선 항목 분석

감시카메라로 쓰는 데 필요한 개선 항목을 펌웨어(part0, `0x80000000` 적재)에서 분석한 결과입니다. 주소는 메모리 주소이며, 파일 위치는 `주소 - 0x80000000`입니다.

## 요약

| # | 항목 | 결론 | 방법 | 패치 규모 | 실기 확인 필요 |
|---|---|---|---|---|---|
| A | 시간·루프 녹화·워터마크·해상도 | **패치 불필요** | HTTP 명령 | - | `par` 값 의미 |
| B-1 | 스테이션 모드 | **완료** (`patch_station.py`) | 분기 고정 | 명령어 19개 | 접속 여부 |
| B-2 | 켜지면 와이파이 자동 시작 | **가능** | 기존 "와이파이 대기" 플래그를 부팅 때 1회 켬 | 코드 동굴 약 12개 + 호출 2곳 | - |
| B-3 | 켜지면 자동 녹화 | **가능, 조건부** | 녹화 키 이벤트 1회 발행, 또는 외부에서 `cmd=2001` | B-2 동굴에 3~4개 추가 | 와이파이 화면에서 녹화 동작 |

## 공통: 코드 동굴(새 코드를 넣을 자리)

B-2, B-3, B-5는 원래 펌웨어에 없는 동작을 추가하므로 새 명령어를 넣을 공간이 필요합니다.

- **위치**: UART 콘솔 명령 `nand erase`의 처리 함수 `0x80077148` (924바이트, 명령어 231개 분량)
- **안전한 이유**: 이 함수를 가리키는 곳은 콘솔 명령 표의 `0x800017dc` 한 곳뿐입니다(직접 호출 0건). 게다가 원래 기능이 "로더를 뺀 NAND 전체 삭제"라 없애는 편이 오히려 안전합니다.
- **처리**: 콘솔 표 `0x800017dc`의 함수 주소를 무해한 `nand dump`(`0x800770f0`, 정보 출력)로 바꾸고, `0x80077148` 자리에 새 코드를 넣습니다.
- 대안: `dsysdma` 처리 함수 `0x800cd144`(920바이트, 콘솔 표 `0x80000b10`에서만 참조)

## A. 패치 없이 되는 설정 (HTTP 명령)

| 설정 | 명령 | 메모 |
|---|---|---|
| 날짜 | `cmd=3005&str=YYYY-MM-DD` | Novatek 공통 형식. 실기 확인 필요 |
| 시간 | `cmd=3006&str=HH:MM:SS` | 위와 같음 |
| 루프 녹화 | `cmd=2003&par=N` | 0 = 꺼짐으로 추정. 1부터 녹화 길이 단계 |
| 날짜 워터마크 | `cmd=2008&par=1` | |
| 녹화 해상도 | `cmd=2002&par=N` | N은 아래 C-3 표의 순번으로 추정(0 = 2880×2160@24 … 4 = 1080p30 … 10 = 720p30). 현재 값은 0인데 T2 표의 0번에는 보조 스트림이 없음에도 RTSP가 나왔으므로, 순번 대응은 실기로 확인해야 합니다 |
| 자동 꺼짐 | `cmd=3007&par=0` | 현재 0(꺼짐) |

감시용 추천: 해상도 `par=4`(1080p30), 루프 녹화 켜기, 워터마크 켜기, 날짜·시간 설정.

## B-2. 켜지면 와이파이 자동 시작

### 현재 구조
- 와이파이 시작은 UI 이벤트 `0x14080092` → `SetupExe_OnWifiStart`(`0x801d8d70`)입니다.
- 이 이벤트는 백그라운드 작업 **12번(`0x12`, `NVTEVT_BKW_WIFI_ON`)**의 함수 `0x801d98d4`가 보냅니다. 작업 표는 `0x8051efd0`에 있습니다.
- 사람이 와이파이를 켤 때와 콘솔 `key i` 명령은 모두 다음 두 줄을 실행합니다(`0x800ce14c`).
  ```
  Ux_OpenWindow(0x8050eea8 /* 와이파이 대기 화면 */, 0)
  BKG_PostEvent(0x12)      // 0x800e884c
  ```
- **무비 화면이 열릴 때 실행되는 함수**(`0x801b9784`, 이벤트 `0x8100`)는 전역 변수 `0x805a0fa0`이 0이 아니면 위 두 줄을 실행하고 변수를 0으로 되돌립니다(`0x801b9988`, `0x801b9a84`). 모드를 바꾼 뒤 와이파이를 다시 켜기 위한 장치입니다.

### 패치 설계
- 무비 화면이 열릴 때 실행되는 함수가 `0x801b9318`을 호출하는 두 곳(`0x801b9980`, `0x801b9a7c`)을 코드 동굴 호출로 바꿉니다. 두 곳 모두 `0x805a0fa0` 검사 직전입니다.
- 코드 동굴 동작:
  ```
  if (once == 0) { once = 1; *(u32*)0x805a0fa0 = 1; }
  goto 0x801b9318;   // 원래 함수로 그대로 넘김 (ra 유지)
  ```
- 결과: 부팅 후 처음 무비 화면이 뜰 때 와이파이가 한 번만 켜집니다. 이후 메뉴나 재생에서 돌아올 때는 다시 켜지지 않습니다.
- `once`는 코드 동굴 안의 데이터 워드에 둡니다(RAM, 초기값 0).

## B-3. 켜지면 자동 녹화

### 현재 구조
- 녹화 버튼(셔터2)은 UI 이벤트 `0x1106010e`입니다. 콘솔 `key shutter2`(`0x800ce17c`)가 다음을 호출합니다.
  `Ux_PostEvent(0x1106010e, 1, 0x11060101)` (`0x800e82c0`)
- 무비 화면 이벤트 표(`0x80516030`~)에서 `0x1106010e`는 `0x801b975c`(녹화 시작·중지)로 연결됩니다.
- HTTP `cmd=2001`은 UI 이벤트 `0x8000e003`이며, 처리기 `0x801b1cbc`(표 `0x80510390`)는 와이파이 연결 중인 화면에서 동작합니다.

### 패치 설계(두 가지 중 선택)
1. **B-2 코드 동굴에 녹화 키 이벤트 1회 발행을 추가**합니다. 와이파이 대기 화면이 열리기 전에 이벤트가 처리되도록 순서를 맞춰야 합니다. 와이파이 화면이 뜬 뒤에는 녹화 키가 그 화면으로 가기 때문입니다. 실기 확인이 필요합니다.
2. **패치 없이**: 중계기나 휴대폰이 접속할 때 `cmd=2001&par=1`을 보냅니다. 스테이션 모드에서 이 명령이 동작하는지만 확인하면 됩니다. 이쪽을 먼저 권합니다.

## B-4. 재접속 무제한

### 현재 구조
- 주기 작업 `WIFI_CliReconnect`(`0x801c81dc`, 주기 값 150)와 접속 직후 처리 함수(`0x801c7ef0`)가 스테이션 모드(`"sta"`)일 때 재접속을 시도합니다.
- 시도 횟수(`0x805a1d8c`)가 **10 이상이면 포기**합니다. 이때 타이머를 멈추고 UI 이벤트 `0x8000e025`(연결 실패)를 보냅니다.

### 패치
| 주소 | 원래 | 변경 |
|---|---|---|
| `0x801c8214` | `slti a0, v1, 0xa` | `slti a0, v1, 0x7fff` (사실상 무제한) |
| `0x801c7f24` | `slti a0, v1, 0xa` | `slti a0, v1, 0x7fff` |

공유기가 재부팅되거나 잠시 꺼져도 계속 재접속합니다. 다만 접속 성공 시 횟수가 0으로 초기화되는지는 확인되지 않았습니다. 그래서 상한을 크게 잡는 방식을 택했습니다.

## B-5. 비상 복귀 (AP 모드로 돌아가기)

스테이션 설정이 틀리면 카메라에 와이파이로 접속할 방법이 없어집니다. 그래서 카메라만으로 AP 모드로 되돌릴 수 있는 방법을 둡니다.

### 설계: SD카드 파일 스위치
- 스테이션 패치에서 모드를 1로 고정한 7곳(`li v0, 1`)을 **코드 동굴의 `get_mode()` 호출**로 바꿉니다. 원래 `jal SysGetFlag` 자리라 명령어 1개 교체로 끝납니다.
- `get_mode()` 동작:
  ```
  if (FileSys_GetAttrib("A:\\M20AP.TXT", &attr) == 성공) return 0;   // AP 모드
  return 1;                                                           // 스테이션
  ```
  `FileSys_GetAttrib` = `0x800eab8c` (`FileSys_OpenFile` `0x800ea8c8`, `FileSys_CloseFile` `0x800ea870`도 사용 가능). 인자 형식은 구현할 때 호출하는 곳을 보고 확정합니다.
- 사용법: PC에서 SD카드에 빈 파일 `M20AP.TXT`를 만들면 AP 모드로 동작합니다. 지우면 다시 스테이션 모드입니다. 펌웨어를 다시 올릴 필요가 없습니다.
- 대안: 연결 실패 이벤트(`0x8000e025`)가 나면 AP로 자동 전환. B-4와 충돌하므로(무제한 재접속이 목표) 파일 스위치를 권합니다.

## C-1. HTTP MJPEG 스트림

- MJPEG 스트림 기능(`ImageUnit_NetHTTP`, 객체 `0x805201a8`)은 **사진 모드 함수들(`PhotoExe_*`, `0x801d2b9c` 등)에서만 연결**됩니다.
- RTSP(`ImageUnit_NetRTSP`, 객체 `0x80520300`)는 동영상 모드(`0x801d0d44`)에서 연결됩니다.
- 즉 동영상 모드에서 `:8192`가 안 열린 게 정상입니다.
- **확인 방법(패치 불필요)**: `cmd=3001&par=0`(사진 모드)으로 바꾼 뒤 브라우저에서 `http://카메라IP:8192`를 엽니다.
- 한계: 사진 모드에서는 동영상 녹화가 안 됩니다. "녹화 + 실시간 보기"가 필요하면 동영상 모드의 RTSP를 써야 합니다.

## C-2. USB 웹캠 (UVC)

- UVC 드라이버(`UVAC_*`, `0x802b8d14`~), USB 동영상 앱(`ImageApp_UsbMovie_*`), 웹캠 실행 함수(`UVACExe_OnOpen` `0x801db2d0`)가 모두 들어 있습니다.
- PC 카메라 모드 ID는 실행 중에 `0x8051f0b8`에 등록되고, 콘솔 `mode pcc`는 `Ux_PostEvent(0x10010002, 1, *0x8051f0b8)`로 들어갑니다.
- 콘솔 외에도 **UI 함수 3곳(`0x801a545c`, `0x801a5790`, `0x801b20c8`)이 PC 카메라 모드로 전환**합니다. USB를 연결할 때 뜨는 선택 메뉴일 가능성이 높습니다.
- **확인 방법**: USB를 PC에 연결했을 때 카메라 화면에 "PC Camera"류 선택지가 뜨는지 봅니다. 뜨면 패치가 필요 없습니다. 안 뜨면 USB 연결 처리에서 PC 카메라 쪽으로 분기를 고정하는 소규모 패치를 하면 됩니다.
- 웹캠 해상도는 `xUvac_ConfigMovieSizeCB`(`0x801db684`)와 `UVAC_ConfigVidReso`(`0x802ba854`)에서 정합니다.

## C-3. 비트레이트

해상도 표가 두 개 있고, 행 순서가 `cmd=2002`의 `par` 값과 같습니다. TBR은 초당 바이트 수입니다.

- **T1**: 와이파이 꺼짐(녹화 1개 경로). 행 간격 0x34
- **T2**: 와이파이 켜짐(녹화 + 실시간 보조 스트림). 스테이션 모드에서는 이 표가 쓰입니다.

| par | 해상도 | T1 TBR 위치 | T2 TBR 위치 | 현재 값 | 보조 스트림 TBR 위치 (현재) |
|---|---|---|---|---|---|
| 0 | 2880×2160@24 | `0x8051abac` | `0x8051ae50` | 20.1 Mbps | 없음 |
| 1 | 2560×1440@30 | `0x8051abe0` | `0x8051ae84` | 20.1 | `0x8051ae9c` (4.1) |
| 2 | 1920×1080@60 | `0x8051ac14` | `0x8051aeb8` | 20.1 | `0x8051aed0` (1.6) |
| 3 | 1920×1080@50 | `0x8051ac48` | `0x8051aeec` | 20.1 | `0x8051af04` (1.6) |
| **4** | **1920×1080@30** | `0x8051ac7c` | `0x8051af20` | **14.7** | `0x8051af38` (1.6) |
| 5 | 1920×1080@25 | `0x8051acb0` | `0x8051af54` | 20.1 | `0x8051af6c` (1.6) |
| 6 | 1440×1080@30 | `0x8051ace4` | `0x8051af88` | 14.7 | `0x8051afa0` (1.6) |
| 7 | 1920×1080@30 | `0x8051ad18` | `0x8051afbc` | 14.7 | `0x8051afd4` (1.6) |
| 8 | 1280×720@120 | `0x8051ad4c` | `0x8051aff0` | 20.1 | `0x8051b008` (1.6) |
| 9 | 1280×720@60 | `0x8051ad80` | `0x8051b024` | 13.1 | `0x8051b03c` (1.6) |
| 10 | 1280×720@30 | `0x8051adb4` | `0x8051b058` | 6.6 | `0x8051b070` (1.6) |
| 11 | 640×480@240 | `0x8051ade8` | `0x8051b08c` | 13.1 | `0x8051b0a4` (1.6) |

- 보조 스트림은 RTSP로 나가는 **640×360@30, 1.6 Mbps** 영상입니다.
- 권장 변경
  - 1080p30 녹화: 1843200 → 2508800 (14.7 → 20.1 Mbps). 다른 해상도가 이미 쓰는 값이라 인코더와 버퍼가 감당할 수 있습니다.
  - RTSP 보조 스트림: 204800 → 409600 (1.6 → 3.3 Mbps). 2.5K 행이 이미 512000을 쓰므로 안전 범위입니다.
- 보조 스트림 **해상도**(640×360)를 올리는 것은 버퍼 크기가 함께 정해져 있을 수 있어서 권하지 않습니다.
- 높은 비트레이트에는 U3급 SD카드가 필요합니다.
