# SJCAM M20 (Novatek NT96660) 펌웨어 도구

`ntkfw.py`는 SJCAM M20 V1.3.1 펌웨어(`SJCAM001.bin`)를 풀고, 수정한 메인 프로그램을 다시 포장하는 도구입니다. Python 3 표준 라이브러리만 사용합니다.

> 펌웨어 파일(`*.bin`)은 제조사 저작물이라 저장소에 넣지 않습니다(`.gitignore`로 제외).

## 펌웨어 구조

| 위치 (원본 기준) | 내용 |
|---|---|
| `0x000000` | **part0**: BCL1 블록. 메인 프로그램(eCos), 메모리 `0x80000000`에 적재 |
| `0x2a4da8` | **NVTPACK_FW_HDR**: GUID, 헤더 크기(0x28), 체크섬, 항목 수, (시작 위치, 크기, ID) 표 |
| `0x2a4dd0` | **part1**: BCL1 블록 |

BCL1 헤더(16바이트): `'BCL1'` · 체크섬 u16 LE · 알고리즘 u16 BE(9 = LZ77) · 풀린 크기 u32 BE · 압축 크기 u32 BE

### 체크섬 3종류 (모두 Novatek `MemCheck_CalcCheckSum16Bit`)

16비트 LE 값과 그 순번을 모두 더했을 때 0이 되도록 보정값을 넣는 방식입니다. 보정값 자리는 0으로 보고 계산합니다.

1. **풀린 데이터 내부**: `0x6C`가 `FF FF`이고 `0x46C`가 `55 AA`이면 `0x46E`(part1이 이 경우), `0x6C`/`0x16C`/`0x26C`에 `55 AA`가 있으면 그 뒤 2바이트(part0은 `0x6E`)가 보정값입니다.
2. **BCL1 헤더**: 압축된 블록 전체(헤더 포함)에 대해 계산하고, 헤더 `+4`에 저장합니다.
3. **NVTPACK_FW_HDR**: 헤더와 표(0x28바이트)에 대해 계산하고, `+0x14`에 저장합니다.

`pack`은 세 가지를 모두 자동으로 다시 계산하고, part0 크기가 바뀌면 표의 part1 시작 위치도 고칩니다.

## 사용법

```sh
python3 ntkfw.py info   SJCAM001.bin                 # 구조와 체크섬 확인
python3 ntkfw.py unpack SJCAM001.bin work/           # work/part0.bin, part1.bin
# ... work/part0.bin 수정 (크기는 그대로) ...
python3 ntkfw.py pack   SJCAM001.bin work/part0.bin new/SJCAM001.bin
python3 ntkfw.py verify new/SJCAM001.bin [work/]     # 다시 읽어서 검증
```

- `pack`은 part0만 다시 압축합니다. part1은 바이트 그대로 복사합니다.
- part0 크기가 달라지면 거부합니다. 코드가 고정 주소에 적재되기 때문입니다.
- 압축기는 원본 압축기와 바이트 단위로 같지는 않지만 같은 BCL LZ77 형식입니다. 기본 모드는 16KB보다 긴 일치와 겹치는 복사를 사용합니다(실기 부팅 확인됨). `--compat`를 주면 원본처럼 일치 길이 16384 이하, 겹침 없음으로 만듭니다(약 5KB 커짐).
- 펌웨어의 업데이트 루틴은 파티션 크기를 넘는 파일을 거부하므로, `pack`은 결과가 입력 펌웨어보다 크면 멈춥니다(`--allow-larger`로 무시 가능).

## 스테이션 모드 패치 (`patch_station.py`)

M20이 자기 AP를 만드는 대신 **집 공유기에 접속**하도록 하는 패치입니다.

```sh
python3 ntkfw.py unpack SJCAM001.bin work/
python3 patch_station.py work/part0.bin work/part0_sta.bin --ssid '공유기이름' --passphrase '비밀번호'
python3 ntkfw.py pack SJCAM001.bin work/part0_sta.bin new/SJCAM001.bin
```

- **실기 확인됨**: 패치 후 카메라 AP가 사라지고, 집 공유기(2.4GHz WPA2)에 접속해 DHCP로 IP를 받았습니다. 집 네트워크에서 HTTP 명령(`cmd=3012`)이 응답하고 80, 554(RTSP), 3333 포트가 열려 있었습니다.
- 결과 파일에는 SSID와 비밀번호가 평문으로 들어갑니다. 공유하거나 커밋하지 마세요.
- 공유기는 2.4GHz와 WPA2-PSK(AES)여야 합니다.
- 원리: 와이파이 시작 함수(`SetupExe_OnWifiStart`, `0x801d8d70`)는 원래부터 `SysGetFlag(0x8b)`가 1이면 스테이션으로 동작하는 분기를 갖고 있습니다. 하지만 이 값은 UART 디버그 명령(`wifi mode 1`)으로만 바뀌고, 스테이션용 SSID와 비밀번호 버퍼도 비어 있습니다. 패치는 이 함수 안에서 모드를 읽는 곳을 1로 고정하고, 함수 전용 디버그 문자열 자리(`0x803b0e2c`~)에 SSID와 비밀번호를 넣어 그 위치를 가리키게 합니다. 설정값 자체는 건드리지 않으므로, 원본 펌웨어로 되돌리면 흔적이 남지 않습니다.
- 스크립트는 바꾸기 전에 각 위치의 원래 명령어를 확인하고, 다르면 중단합니다(V1.3.1 전용).

## 적용 순서 (안전 절차)

1. **무수정 왕복 테스트**: 아무것도 고치지 않은 `part0.bin`으로 `pack` → SD카드 루트에 `SJCAM001.bin`으로 복사 → 업데이트 → 정상 부팅과 동작 확인.
   이게 통과해야 도구(압축과 체크섬)가 카메라에서도 유효하다고 볼 수 있습니다.
2. 그다음에 실제 수정을 적용합니다.
3. 문제가 생기면 원본 `SJCAM001.bin`으로 SD카드 업데이트를 하면 원래대로 돌아갑니다. 부팅이 되는 한 가능합니다.

SD카드는 FAT32로 포맷하고, 업데이트 중에는 전원을 끊지 마세요. 업데이트가 끝나면 카드에서 `.bin` 파일을 지웁니다.

## 함수·명령 목록

`M20_FUNCTIONS.md`: HTTP 명령 61개, UART 콘솔 명령 400여 개, 이름이 확인된 함수 3,000여 개와 수정 후보를 정리했습니다. 다시 만들려면 `python3 catalog.py work/part0.bin`을 실행합니다(맨 위의 수정 후보 표는 직접 작성한 부분).

- `ANALYSIS.md`: 감시카메라용 개선 항목(자동 와이파이, 자동 녹화, 재접속, 비상 복귀, MJPEG, USB 웹캠, 비트레이트) 분석과 패치 설계

## 추가 패치 (`patch_extra.py`)

스테이션 패치를 적용한 part0(또는 원본)에 이어서 적용합니다. 바꾸기 전에 원래 값을 확인합니다.

```sh
python3 patch_extra.py work/part0_sta.bin work/part0_x.bin --led-off --reconnect [--live720]
python3 ntkfw.py pack SJCAM001.bin work/part0_x.bin new/SJCAM001.bin
```

| 옵션 | 내용 |
|---|---|
| `--led-off` | 파란(와이파이) 표시등을 항상 끔. GPIO `0x5b`를 켜는 유일한 함수(`0x800c9094`)가 끄도록 변경. **실기 확인됨** |
| `--reconnect` | 스테이션 재접속 10회 제한(`0x801c8214`, `0x801c7f24`)을 0x7fff로 |
| `--leds-off` | 상태 표시등(GPIO `0x5a`/`0x5c`/`0x5d`, 노란색·위쪽 파란색 등)을 부팅 후 항상 끔. 이 핀들을 켜는 유일한 함수(`0x800c9154`) 안의 켜기 8곳을 끄기로 변경. 충전 표시등처럼 하드웨어가 직접 켜는 불은 해당 없음 **실기 확인됨** |
| `--mute` | 버튼음·셔터음·전원 켜기/끄기 음 등 효과음 제거. 소리 재생 작업에서 유일한 재생 호출(`0x8029569c`)을 없앰. 녹음과 영상 소리는 별도 경로라 영향 없음 **실기 확인됨** |
| `--autowifi` | 부팅 후 처음 무비 화면이 열릴 때 와이파이를 자동으로 켬(스테이션 패치 필요). 무비 화면 열기 함수의 기존 "와이파이 대기"(`0x805a0fa0`) 처리를 이용하며, 새 코드 8개를 콘솔 `nand erase` 처리 함수 자리(`0x80077148`)에 넣고 그 콘솔 명령은 `nand dump`로 돌림. **실기 확인됨**(E 이후 모든 빌드) |
| `--live15` | 실시간 보조 스트림을 15fps로(압축량 절반, 발열 감소). **실기 확인됨**: 2.5K 녹화 중 1280×720@15, 약 1.65Mbps, 20초 301프레임 |
| `--apfile` | SD카드에 `M20AP.TXT`(내용 아무거나, 웹 업로드는 빈 파일을 거부)가 있으면 원래처럼 AP 모드, 없으면 스테이션 모드(스테이션 패치 필요). 와이파이 시작·종료 코드의 "모드=1" 7곳을 `get_mode()` 호출로 바꾸고, 결과는 부팅마다 한 번 확인해 저장. 코드는 콘솔 `dsysdma` 처리 함수 자리(`0x800cd144`). E에서는 `FileSys_GetAttrib`로 확인했는데 파일이 있어도 AP로 바뀌지 않아서, F4부터 `FileSys_OpenFile`/`CloseFile`로 확인함. 결과는 `cmd=3012` 첫 문자열 3번째 글자: `S` 파일 없음, `T` 있음(파일 없음 `S`는 실기 확인) |
| `--defaults` | 업데이트·초기화 후 기본값: 녹화 2560×1440@30(설정값 `0x1a`=1, HTTP `2002`=0), 자동 꺼짐 끔(`0x3a`=0). 설정값 `0x1a`는 해상도 표 순번(0 = 2880×2160@24)이고 HTTP 2002는 1/2/4/8/9…를 0/1/2/3/4…로 보여 줌(`0x801cad44`). 와이파이 연결 화면(`0x801b1f14`)은 0과 0xb를 2(1080p60)로 바꿔서, E(`0x1a`=0)는 1080/60으로 나왔음. 차량 모드(`0xa1`)는 녹화 키가 와이파이 대기 화면에 먹혀 효과가 없어 F부터 넣지 않음. **실기 확인됨**(F: 2002=0, 3007=0) |
| `--autorec` | 버튼 없이 녹화 시작. 와이파이 연결 화면(`UIMenuWndWiFiMobileLinkOK`, 공유기에서 IP를 받으면 열림)의 0.5초 타이머(`0x801b084c`)에 연결해, 4초마다 최대 2분 동안 녹화 상태(`0x801bfa38`: 1 준비, 2 녹화 중)를 보고 준비면 `cmd=2001&par=1`과 같은 UI 이벤트 `0x8000e003`(par 1)을 보냄. 녹화를 확인하면 그 부팅에서는 멈춤(손으로 멈춘 녹화를 다시 켜지 않음). 진행 상황은 `cmd=3012` 첫 문자열 1·2번째 글자(`a1` = 첫 시도에 준비 상태라 시작, `b2` = 둘째 시도에 녹화 확인). 공유기 연결 전에는 녹화하지 않음. F(3초 뒤 한 번만 시도)는 실패, F2 이후 **실기 확인됨**(약 21Mbps) |
| `--binclean` | 카드에 `SJCAM001.bin`이 있으면 원래 펌웨어는 화면과 와이파이를 켜지 않고 멈춤(`0x801c6724`가 파일을 열면 `0x8055c33c`=1). 업데이트는 그 전에 로더가 이미 끝냄. 이 옵션은 멈추지 않고 정상 부팅한 뒤, `--autorec`의 첫 시도 때 파일을 지움. 부팅 직후 지우기(F3)와 부팅 때 세운 표시로 나중에 지우기(F4)는 실패, F5 방식 **실기 확인됨** |
| `--reboot-cmd` | HTTP `cmd=9002`(원래: `cmd=2022`와 같은 값을 읽기만 함)를 원격 재부팅으로. 응답 후 `--autorec` 타이머 코드가 녹화 중이면 먼저 멈추고 파일이 닫히면(최대 10초) USB 펌웨어 업데이트 끝에 쓰는 `0x80014978(5, 0xff)`("(sw-reset)", 워치독 리셋)를 부름. **실기 확인됨**: 1초 안에 녹화 정지, 직전 파일 정상 재생, 약 75초 뒤 복귀해 자동 녹화 |
| `--default-date YYYY-MM-DD` | 부팅 때 시계 날짜가 기준보다 이전이면 맞추는 기본값(원래 2015-12-22 미만이면 2016-01-01 00:00:01, `System_OnBoot` `0x800cbaa0`)을 기준·날짜 모두 바꿈. 펌웨어에 SNTP/NTP 클라이언트는 없음. 실기에서는 외부에서 `cmd=3005`/`3006`을 보내는 시계 맞춤이 먼저 동작해 이 값은 따로 확인하지 못함 |
| `--live720` | 와이파이 실시간 보조 스트림(RTSP)을 640×360 → 1280×720, 목표 512000B/s(약 4Mbps). 이중 스트림 표 `0x8051ae44`의 2.5K~720p 행. **실기 확인됨**(2.5K 녹화 중 정상 동작) |

### 빌드 기록 (2026-11-10, 모두 `--led-off --reconnect --leds-off --mute --live720 --live15 --autowifi --apfile --defaults` 포함)

| 빌드 | 추가 | 실기 결과 |
|---|---|---|
| E | `--defaults`(0x1a=0, 차량 모드) | 1080/60으로 나옴, 자동 녹화 안 됨 |
| F | `--defaults` 수정, `--autorec`(3초 뒤 한 번) | 2002=0·3007=0 정상, 자동 녹화 안 됨. 카드에 .bin이 남아 있으면 화면이 꺼진 채 멈춤 |
| F3 | `--autorec` 재시도, `--binclean`(부팅 때 삭제) | 자동 녹화 성공. .bin은 안 지워졌지만 정상 부팅해서 웹으로 지움 |
| F4 | `--apfile` OpenFile 방식, 삭제를 나중에 | 자동 녹화 성공, `S` 표시. .bin 삭제 실패 |
| F5 | `--reboot-cmd`, `--default-date 2026-11-10`, 첫 시도 때 무조건 삭제 | 설치 후 .bin 자동 삭제, 자동 녹화(`a1`), 원격 재부팅 성공 |

## 무선 업데이트 (F5 이후)

1. 카메라 웹 첫 페이지의 "Upload files" 폼과 같은 방식으로 올림: `curl -F "fileupload1=@SJCAM001.bin" http://카메라IP/` (같은 이름의 파일이 있으면 거부되므로 먼저 `http://카메라IP/SJCAM001.BIN?del=1`로 지움). 다시 받아서 해시 비교 권장.
2. `curl "http://카메라IP/?custom=1&cmd=9002"`로 재부팅. 로더가 업데이트하고, 새 펌웨어가 첫 녹화 시도 때 .bin을 지움.
3. `cmd=3012` 첫 문자열과 `cmd=2016`, 3014(2002·3007)로 확인.

- 웹 첫 페이지의 `?del=1` 링크와 `cmd=4003&str=A:\파일`로 파일 하나를 지울 수 있음(실기 확인).
- "Upload Custom files"(`?custom=1`, HTTP PUT → `cmd=5001` 처리기 `0x801cb0a0`)는 `par`가 0이 아니면 받은 내용을 검증 없이 펌웨어 영역에 바로 씀(FwSrv 명령 3). 쓰지 않음.
- 카메라를 손으로 꺼야 할 때는 카드에 .bin이 없어야 함(F5 이전 펌웨어).

## 웹 조작 페이지 (`web/M20.HTM`)

SD카드 맨 위 폴더에 넣으면 카메라 웹서버가 그대로 보여 줍니다(`http://카메라IP/M20.HTM`). 실기에서 페이지로 열리는 것을 확인했습니다. 펌웨어 수정 없이 동작하며, 녹화 상태(`cmd=2016`은 경과 시간이 아니라 녹화 중 1/정지 0) 표시, 녹화 시작·정지, 모드 전환, 폰 시간으로 시계 맞추기, 루프 녹화·날짜 표시·녹음·해상도 설정, RTSP 주소와 VLC 열기, DCIM 폴더 링크를 제공합니다. 포맷·초기화·삭제 명령은 넣지 않았습니다.

펌웨어를 업데이트하면 카메라 설정(녹화 해상도, 자동 꺼짐 등)이 기본값으로 돌아가므로 다시 설정해야 합니다.
